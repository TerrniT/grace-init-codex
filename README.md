# GRACE Init для Codex: установка, запуск и рабочий процесс

Ниже — практическая инструкция, как:
1) подключить `grace-init-codex` в ваш проект;
2) запустить инициализацию;
3) работать дальше с агентными инструкциями, которые появятся после `grace-init`.

---

## 1. Что это такое

`grace-init-codex` — это инициализатор, который из шаблонов генерирует стартовые GRACE-документы для проекта, где **Codex — главный агент**.

Скрипт автоматически:
- читает шаблоны `*.template`;
- находит плейсхолдеры (`$PROJECT_NAME`, `$OWNER`, ...);
- спрашивает значения 1 раз и подставляет во все файлы;
- обрабатывает конфликты при существующих файлах (`backup / skip / overwrite`);
- создает `AGENTS.md` (и при необходимости синхронизирует его с `CLAUDE.md`).

---

## 2. Как добавить `grace-init-codex` в проект для Codex

Есть два рабочих способа.

### Вариант A (рекомендуется): хранить skill в репозитории проекта

Скопируйте директорию skill в ваш проект:

```bash
mkdir -p .agents/skills
cp -R /path/to/grace-init-codex/.agents/skills/grace-init-codex .agents/skills/
```

После этого в вашем проекте должны быть:
- `.agents/skills/grace-init-codex/scripts/grace_init.py`
- `.agents/skills/grace-init-codex/assets/templates/*`
- `.agents/skills/grace-init-codex/SKILL.md`

Плюс этого подхода: версия инициализатора фиксируется прямо в репозитории и одинакова для всей команды.

### Вариант B: запускать инициализатор из внешнего репозитория

Если не хотите копировать skill, можно запускать его из этого репозитория, а target указывать на ваш проект:

```bash
python3 /path/to/grace-init-codex/.agents/skills/grace-init-codex/scripts/grace_init.py \
  --target-dir /path/to/your-project
```

---

## 3. Запуск инициализации в проекте

Из корня проекта:

```bash
python3 .agents/skills/grace-init-codex/scripts/grace_init.py
```

Или с явными путями:

```bash
python3 .agents/skills/grace-init-codex/scripts/grace_init.py \
  --templates-dir .agents/skills/grace-init-codex/assets/templates \
  --target-dir .
```

Скрипт интерактивно попросит заполнить значения для плейсхолдеров (например: `PROJECT_NAME`, `DOMAIN`, `OWNER`, `KEYWORDS`, `ANNOTATION`).

---

## 4. Что появляется после `grace-init`

Минимально вы получите:

- `AGENTS.md` — основной файл инструкций для агентной работы Codex в репозитории.
- `CLAUDE.md` — параллельный GRACE-документ (если используется в вашей схеме).

Если `CLAUDE.md` уже создан, а `AGENTS.md` отсутствует, инициализатор создаст `AGENTS.md` на основе `CLAUDE.md`.

---

## 5. Как дальше работать с агентами после инициализации

### Шаг 1. Сделайте `AGENTS.md` источником правил

Сразу после генерации проверьте и уточните:
- роль Codex (главный агент/оркестратор);
- правила изменения кода;
- требования к тестам, коммитам и PR;
- структуру документации (`docs/` как source of truth).

### Шаг 2. Добавьте уровни инструкций (при необходимости)

Вы можете создавать дополнительные `AGENTS.md` в подпапках проекта.
Тогда правила работают по области видимости:
- корневой `AGENTS.md` — для всего репозитория;
- вложенный `AGENTS.md` — для своей директории и ниже;
- более глубокий файл приоритетнее (если есть конфликт).

Это удобно, например, чтобы отдельно задать правила для:
- `backend/`
- `frontend/`
- `infra/`

### Шаг 3. Ведите GRACE-артефакты синхронно с кодом

Если меняете контракты, архитектуру или процессы — обновляйте соответствующие документы одновременно с кодом, а не постфактум.

### Шаг 4. Используйте единый шаблон постановки задач для Codex

Рекомендуемый формат задачи:
1. Контекст (что меняем и зачем)
2. Ограничения (что нельзя ломать)
3. Definition of Done
4. Какие проверки обязательно прогнать
5. Требования к коммиту/PR

Так Codex стабильно опирается на `AGENTS.md` и выдает предсказуемый результат.

---

## 6. Конфликты файлов при повторном запуске

Если файл уже существует, `grace_init.py` спросит действие:
- `b` — backup (сделать резервную копию и перезаписать)
- `s` — skip (пропустить)
- `o` — overwrite (перезаписать)
- `b! / s! / o!` — применить ко всем оставшимся конфликтам

Это позволяет безопасно переинициализировать проект после обновления шаблонов.

---

## 7. Рекомендуемый рабочий цикл команды

1. Добавили skill в репозиторий (`.agents/skills/grace-init-codex`).
2. Запустили `grace_init.py`.
3. Проверили и донастроили `AGENTS.md` под реальные процессы.
4. Закоммитили агентные файлы в `main`.
5. Все дальнейшие задачи для Codex выполняются с опорой на эти инструкции.
6. При изменении процессов — обновляете `AGENTS.md` и связанные документы вместе с кодом.
