# Как запускать GRACE Init для Codex-проекта

Этот репозиторий содержит фреймворк-инициализатор `grace-init-codex`, который разворачивает базовые GRACE-документы из шаблонов и помогает настроить проект, где **Codex — главный агент**.

## Что делает фреймворк

Скрипт:
- читает все шаблоны `*.template` из `assets/templates/`;
- находит плейсхолдеры вида `$PLACEHOLDER` и спрашивает значения один раз;
- генерирует итоговые файлы в целевом проекте;
- при конфликтах файлов предлагает `backup / skip / overwrite`;
- если создан `CLAUDE.md`, но нет `AGENTS.md`, дублирует `CLAUDE.md` в `AGENTS.md`.

## Требования

- Python 3.10+ (или совместимая версия Python 3).
- Доступ к каталогу проекта, куда нужно сгенерировать файлы.

## Быстрый запуск (в текущем репозитории)

Из корня репозитория выполните:

```bash
python3 .agents/skills/grace-init-codex/scripts/grace_init.py
```

Скрипт интерактивно запросит значения для плейсхолдеров (например: `PROJECT_NAME`, `DOMAIN`, `OWNER`, `KEYWORDS`, `ANNOTATION`) и создаст файлы в текущей директории.

## Запуск для другого проекта (где Codex — главный агент)

### Вариант 1: запуск из этого репозитория в внешний проект

```bash
python3 .agents/skills/grace-init-codex/scripts/grace_init.py \
  --target-dir /path/to/your-project
```

### Вариант 2: если скопировали skill в проект

```bash
python3 .agents/skills/grace-init-codex/scripts/grace_init.py \
  --templates-dir .agents/skills/grace-init-codex/assets/templates \
  --target-dir .
```

## Как использовать в проекте с Codex как главным агентом

1. Сгенерируйте `AGENTS.md` и `CLAUDE.md` через `grace_init.py`.
2. Зафиксируйте в `AGENTS.md`, что Codex — основной агент и какие у него правила работы в репозитории.
3. Ведите процессные документы в `docs/` (по GRACE-принципу — как источник правды).
4. При изменениях кода обновляйте процессные/контрактные документы синхронно.

## Поведение при существующих файлах

Если файл уже существует, скрипт предложит:
- `b` — backup (создать резервную копию и перезаписать);
- `s` — skip (пропустить файл);
- `o` — overwrite (перезаписать);
- `b! / s! / o!` — применить выбор ко всем оставшимся конфликтам.

## Рекомендуемый рабочий цикл

1. Инициализация: запустить `grace_init.py`.
2. Проверка: убедиться, что `AGENTS.md` и `CLAUDE.md` отражают реальные правила проекта.
3. Разработка: выполнять задачи через Codex с опорой на `AGENTS.md`.
4. Поддержка: при эволюции проекта обновлять шаблоны и повторно прогонять инициализатор при необходимости.
